CATATAN PERUBAHAN BESAR DI VERSI 3.0 (baca dulu sebelum baca bagian lain):

  0. PERUBAHAN ARSITEKTUR PALING BESAR di revisi ini -- hasil diskusi
     ulang sistem fisik yang sebenarnya mau dibangun Agung, TERNYATA BEDA
     dari yang digambarkan proposal tertulis:
     - Kolektor -> tangki: PASIF (thermosiphon, air naik sendiri karena
       beda massa jenis panas-dingin), BUKAN dipompa. Tidak ada aktuator
       elektronik di jalur ini.
     - Tangki -> keran: SATU pompa 12V/5A, fungsinya cuma ANTAR AIR ke
       titik pakai (distribusi), dipakai siang-malam sesuai permintaan
       user, TIDAK ADA HUBUNGANNYA dengan pengaturan suhu.
     - Sumber panas: SIANG = kolektor surya (pasif), MALAM = heater
       listrik (aktif, backup).
     - KONSEKUENSI: karena pompa bukan lagi aktuator yang mempengaruhi
       suhu, PID PINDAH ke HEATER (bukan lagi ke pompa seperti versi
       1.x/2.x). Pompa jadi kontrol ON/OFF sederhana dengan gerbang suhu
       (lihat bagian 3 & 9).
     - !! PERINGATAN UNTUK AGUNG (disampaikan lewat Asad, WAJIB
       ditindaklanjuti ke dosen pembimbing) !!: proposal tertulis yang
       sudah di-ACC (Diagram Blok Kontrol Gambar 3.10, Flowchart Gambar
       3.11) menggambarkan PID->PWM->KECEPATAN POMPA, dan Batasan Masalah
       poin 5 bahkan menyatakan "tanpa mempertimbangkan sumber pemanas
       cadangan (auxiliary heater)". Sistem yang direalisasikan sekarang
       (thermosiphon pasif + PID di heater + pompa cuma distribusi) BEDA
       CUKUP BESAR dari dokumen yang disetujui dosen. Ini perlu
       dikonfirmasi/didiskusikan ke dosen pembimbing SEBELUM sidang --
       bukan keputusan yang bisa diambil sepihak di level PCB/firmware.
  1. MCU ganti Arduino Mega 2560 -> ESP32 DevKit, atas permintaan client.
     KONSEKUENSI PENTING: level logic ESP32 = 3.3V (BUKAN 5V seperti Mega).
     Semua pin I/O ESP32 TIDAK toleran 5V -- kalau ada sinyal 5V nyasar ke
     GPIO ESP32 (mis. dari LCD backpack yang di-supply 5V dengan pull-up
     I2C ke VCC-nya), risiko GPIO/chip rusak permanen. Ini bukan sekadar
     beda pinout, tapi beda domain tegangan yang wajib ditangani serius --
     lihat bagian 2 dan 6.
  2. Heater sekarang pakai SSR (solid state relay, bukan relay mekanik)
     karena PID time-proportional control (nyala-mati cepat berulang tiap
     siklus, mis. window 1 detik) akan mengaus kontak relay mekanik dalam
     waktu singkat. SSR solid-state, tidak ada bagian bergerak, aman
     di-switch sesering apapun. Tetap di jalur AC/PLN terpisah (tidak
     berubah dari keputusan sebelumnya).
  3. Pompa sekarang pakai relay DISKRIT (transistor+relay bare+flyback),
     BUKAN modul MOSFET PWM lagi -- karena pompa tidak lagi butuh
     modulasi kecepatan (lihat poin 0). Ini desain yang sebelumnya
     dipakai untuk heater di versi 1.x/2.x, sekarang dipindah ke pompa.
  4. Sizing panel/baterai (bagian 1) pakai ASUMSI: PSH (peak sun hour)
     Madura/Jatim ~4 jam/hari -- WAJIB dicek ke data irradiance riil
     (PVGIS/NASA POWER utk koordinat lokasi tugas akhir) sebelum beli part
     final, ini estimasi perencanaan awal, bukan angka final.

CATATAN PERUBAHAN DI VERSI 3.1:

  5. Pompa BALIK ke MOSFET diskrit (IRLB8721PbF), gantikan relay diskrit

  6. Rotary encoder + push button DIHAPUS, diganti web page + WebSocket

     tanpa komponen tambahan) -- EKSPLISIT discope-kan "buat demo dulu"

     status lokal. Lihat bagian 6 & 9. KONSEKUENSI: power budget bagian 1
     BELUM direvisi utk beban WiFi aktif terus-menerus -- lihat TBD.
  7. Rail suplai logic dipecah jadi 2 buck converter terpisah: BUCK_ESP
     (12V->7V, khusus ESP32) dan BUCK_LCD (12V->5V, khusus LCD) --

     punya masalah transient serupa. Lihat bagian 2 utk detail lengkap.

1. POWER INPUT & DISTRIBUSI (RAIL 12V DC — pompa + logic, DARI PANEL SURYA)
--------------------------------------------------------------------------------

; DIKONFIRMASI dari client: pompa DC = 12V, 5A (60W). Rail 12V ini SEKARANG
; disuplai dari panel surya + baterai (bukan adaptor AC-DC dari PLN lagi),
; atas permintaan client -- heater AC 500W TETAP di PLN terpisah (lihat
; topologi & catatan versi 2.0 di awal file).
;
; === PERHITUNGAN SIZING PANEL SURYA + BATERAI ===
; Asumsi (WAJIB verifikasi ke data irradiance riil sebelum beli part final):
;   - PSH (peak sun hour) Madura/Jatim ~4 jam/hari (estimasi konservatif,
;     cek PVGIS/NASA POWER utk koordinat lokasi TA -- musim hujan bisa
;     lebih rendah dari ini)
;   - Efisiensi sistem (charge controller+kabel+suhu+debu) ~75%
;   - Pompa jalan 8 jam/hari (jam kerja kolektor efektif), worst-case
;     duty 100% (5A kontinu) -- sengaja dipakai angka worst-case, bukan
;     rata-rata, konsisten dengan gaya desain "paling robust" di proyek ini
;   - Beban logic (ESP32+sensor+LCD) ~1.5W rata-rata, nyala 24 jam --
;     !! BELUM DIREVISI DI v3.1 !!: angka ini dari era encoder (idle-ish,
;     WiFi off). Sekarang WiFi ESP32 AKTIF terus (web server+WebSocket
;     utk setpoint) -- ESP32 dgn WiFi aktif tipikal jauh lebih boros
;     drpd idle (ASUMSI kasar ~80-150mA rata-rata saat WiFi connected,
;     vs <50mA tanpa WiFi -- perlu verifikasi ke datasheet/measurement
;     modul devkit spesifik). Wh/day di bawah ini KEMUNGKINAN under-
;     estimate sampai direvisi -- lihat TBD baru di bagian akhir file.
;
; Energi harian dibutuhkan:
;   Pompa   : 60W x 8 jam = 480 Wh/hari
;   Logic   : 1.5W x 24 jam = 36 Wh/hari (ASUMSI LAMA, WAJIB direvisi naik
;             krn WiFi aktif -- lihat catatan di atas)
;   TOTAL   : ~520 Wh/hari (ASUMSI LAMA, kemungkinan naik sedikit)
;
; Panel surya: 520 / (4 PSH x 0.75 efisiensi) = ~173 Wp -> DIBULATKAN ke
; atas dengan margin ~20% -> REKOMENDASI: PANEL 200 Wp (mono/polycrystalline,
; ukuran umum ~100x150cm, banyak tersedia lokal)
;
; Baterai (autonomy 1 hari -- sesuai keputusan client, artinya baterai
; harus bisa nutup 1 hari penuh operasi tanpa matahari sama sekali):
;   - Lead-acid/AGM (DoD aman 50%): 520/0.5 = 1040 Wh -> /12V = ~87Ah ->
;     REKOMENDASI: 12V / 100Ah deep-cycle (lebih murah, lebih berat,
;     cycle life lebih pendek)
;   - LiFePO4 (DoD aman 80%): 520/0.8 = 650 Wh -> /12.8V = ~51Ah ->
;     ALTERNATIF: 12.8V / 55-60Ah (lebih ringan, cycle life jauh lebih
;     panjang, harga awal lebih tinggi -- makin terjangkau & makin umum
;     dijual lokal Indonesia)
;   PILIH SALAH SATU sesuai budget client -- keduanya valid secara teknis,
;   MPPT controller di bawah harus di-set profil charging yang sesuai
;   (lead-acid vs lithium beda kurva charging, JANGAN pakai profil yang
;   salah -- bisa merusak baterai atau bikin umur pakai jauh lebih pendek).
;
; Charge controller: panel 200Wp @ ~18-20V Vmp -> arus kerja ~10-11A ->
; REKOMENDASI: MPPT 20A (lebih efisien dari PWM terutama saat suhu panel
; tinggi/pencahayaan tidak ideal, harga kelas ini sudah terjangkau)

BATERAI_12V [PIN_POS] -> FUSE_MAIN (8A slow-blow) [PIN_A]
FUSE_MAIN [PIN_B] -> D_REVPOL (schottky SB1040, 10A/40V) [PIN_ANODE]
D_REVPOL [PIN_CATHODE] -> SW_MAIN [PIN_A]
SW_MAIN [PIN_B] -> NET_12V_BUS
BATERAI_12V [PIN_NEG] -> NET_GND_BUS

; D_REVPOL DIREVISI dari SS54 (5A) ke SB1040 (10A/40V) -- SS54 sudah
; mepet/kurang begitu pompa ternyata 5A (diode ini menanggung SELURUH
; arus bus 12V, bukan cuma logic).

; === PROTEKSI TAMBAHAN ===
; D_REVPOL: proteksi kalau jack DC/adaptor kesalahan polaritas -- kesalahan
; pemasangan yang sering terjadi di alat rakitan sendiri. Schottky dipilih
; supaya drop tegangan kecil (~0.4-0.5V), sisa tegangan (>11.5V) masih
; jauh di atas kebutuhan minimum buck converter (butuh >6V input).
;
; TVS_12V: opsional, tapi disarankan karena ada MOSFET pompa yang bisa
; menghasilkan spike tegangan balik saat switching. Pasang paralel,
; sedekat mungkin ke titik masuk, sebelum C_12V_BULK.
; SMBJ18A itu UNIDIRECTIONAL (bukan simetris) -- polaritas WAJIB benar,
; beda dari TVS bidirectional (varian "CA", mis. SMBJ18CA) yang gak
; punya polaritas. Sudah dicek ke datasheet resmi Littelfuse: standoff
; 18V (VRWM, bukan tegangan clamp -- ini cuma tegangan kerja normal di
; bawahnya dia idle), breakdown 20.0-22.1V @1mA, clamp maksimum
; sebenarnya 29.2V @arus pulsa puncak. Fisik: kathode ditandai PITA/BAND
; di badan komponen (sama kayak dioda rectifier biasa).
TVS_12V (SMBJ18A, standoff 18V/clamp maks 29.2V, opsional) [PIN_KATODE] -> NET_12V_BUS  ; sisi BERPITA
TVS_12V                                                     [PIN_ANODE]  -> NET_GND_BUS

; === DISTRIBUSI 12V BUS ===
NET_12V_BUS
  -> FUSE_PUMP (7A) [PIN_A]   ; driver MOSFET + pompa -- REVISI dari 2.5A,
                                ; sesuai pompa 5A DIKONFIRMASI + margin ~1.4x
  -> FUSE_BUCK (1A) [PIN_A]   ; dipakai bersama BUCK_ESP + BUCK_LCD, lihat bag.2

; === BULK DECOUPLING DI TITIK DISTRIBUSI ===
C_12V_BULK (1000uF/25V) [PIN_POS] -> NET_12V_BUS
C_12V_BULK               [PIN_NEG] -> NET_GND_BUS
C_12V_CER  (100nF/50V)   [PIN_1]   -> NET_12V_BUS
C_12V_CER                [PIN_2]   -> NET_GND_BUS

NET_GND_BUS -> semua titik GND sistem (star ground, lihat bagian 8)

2. BUCK CONVERTER - RAIL 7V (ESP32) + RAIL 5V (LCD) + LDO 3.3V (sensor)
--------------------------------------------------------------------------------

; REVISI (v3.1): rail logic dipecah jadi DUA buck converter terpisah,
; bukan satu lagi -- atas masukan client berdasarkan pengalaman lapangan
; 14 proyek ESP32: devkit yang disuplai persis di sekitar 5V sering
; "WiFi gak muncul" (gagal connect/browni ng sesaat pas WiFi transmit).
; MEKANISME (dikonfirmasi masuk akal secara teknis): ESP32 narik ARUS
; SPIKE sesaat pas transmit WiFi (bisa 300-500mA sesaat, jauh di atas
; rata-rata). Kalau VIN cuma pas-pasan di ~5V, regulator AMS1117 onboard
; devkit butuh headroom (dropout, makin gede pas arus tinggi) di atas
; 3.3V -- begitu ada spike arus dan tegangan sumber sedikit "ambles"
; (drop kabel, respons regulator kurang cepat), tegangan bisa jatuh di
; bawah ambang minimum itu sesaat, ESP32 brief-brownout pas lagi coba
; connect WiFi. Kasih VIN dengan margin lebih (7V) mencegah ini karena
; walau ada ambles sesaat, tetap di atas ambang minimum regulator.
; TRADE-OFF yang disadari: 7V ke regulator onboard devkit itu buang lebih
; banyak panas drpd 5V (P=(Vin-3.3)xI -- di 7V kira2 2x lebih panas drpd
; di 5V pada arus yang sama), TAPI reliabilitas WiFi lebih penting drpd
; efisiensi teoritis buat sistem yang harus jalan pas sidang. LCD TIDAK
; ikut rail 7V ini -- LCD gak punya masalah transient kayak WiFi, cukup
; rail 5V biasa (lebih dingin, gak ada alasan dikasih lebih).
; C_ESP_ELCO (100uF, di bawah) WAJIB ditaruh SEDEKAT MUNGKIN ke pin VIN
; devkit di PCB -- bantu redam spike arus WiFi secara lokal, lapisan
; proteksi tambahan di luar soal besar tegangan VIN itu sendiri.

; CATATAN: FUSE_BUCK (1A) dipakai BERSAMA oleh dua buck di bawah (bukan
; fuse terpisah per buck) -- sengaja disederhanakan karena arus total
; gabungan ESP+LCD di sisi 12V kecil banget (order ratusan mA), gak perlu
; proteksi terpisah buat kasus sekecil ini. Kalau mau lebih konservatif,
; boleh tambah fuse kedua, tapi bukan keharusan.

; === RAIL 7V KHUSUS ESP32 (BUCK_ESP) ===
FUSE_BUCK [PIN_B] -> BUCK_ESP (XL4015 atau sejenis, adjustable, di-set 7V, >=1A) [PIN_IN+]
NET_GND_BUS       -> BUCK_ESP [PIN_IN-]
BUCK_ESP [PIN_OUT+] -> NET_7V_ESP
BUCK_ESP [PIN_OUT-] -> NET_GND_BUS

; Suplai ESP32 devkit LANGSUNG ke pin 5V/VIN board (nama silkscreen board
; biasanya tetap "5V" walau yang masuk 7V -- itu cuma nama pin, bukan
; berarti board TIDAK toleran >5V, devkit ini sudah dikonfirmasi jalan
; baik di 7V dari pengalaman client). JANGAN feed ke pin 3V3 board (itu
; OUTPUT regulator onboard, bukan input -- feed situ bisa merusaknya).
; Pin 3V3 board TIDAK dipakai sbg sumber eksternal -- semua sensor/
; pull-up eksternal ambil dari LDO_3V3 terpisah (lihat bawah), supaya
; beban sensor eksternal tidak numpang di regulator kecil bawaan devkit.
NET_7V_ESP  -> ESP32_DEVKIT [PIN_5V_VIN]
NET_GND_BUS -> ESP32_DEVKIT [PIN_GND]
C_ESP_ELCO (100uF/16V) [PIN_POS] -> ESP32_DEVKIT [PIN_5V_VIN]  ; WAJIB dekat pin, lihat catatan di atas
C_ESP_ELCO              [PIN_NEG] -> NET_GND_BUS

; === RAIL 5V UNTUK LCD (BUCK_LCD) ===
FUSE_BUCK [PIN_B] -> BUCK_LCD (XL4015 atau sejenis, adjustable, di-set 5V, >=1A) [PIN_IN+]
NET_GND_BUS       -> BUCK_LCD [PIN_IN-]
BUCK_LCD [PIN_OUT+] -> NET_5V_LOGIC   ; nama net dipertahankan "NET_5V_LOGIC" -- sekarang isinya cuma LCD + input LDO_3V3, bukan lagi ESP32
BUCK_LCD [PIN_OUT-] -> NET_GND_BUS

; Decoupling output 5V (LCD)
C_LOG_ELCO (470uF/16V) [PIN_POS] -> NET_5V_LOGIC
C_LOG_ELCO              [PIN_NEG] -> NET_GND_BUS
C_LOG_CER  (100nF)      [PIN_1]   -> NET_5V_LOGIC
C_LOG_CER               [PIN_2]   -> NET_GND_BUS

; === LDO 3.3V (khusus sensor: DS18B20 x2, BH1750, sisi LV level shifter) ===
; Diambil dari NET_5V_LOGIC (rail LCD, murni 5V) -- BUKAN dari NET_7V_ESP,
; supaya AMS1117 di sini cuma nurunin selisih kecil (5-3.3=1.7V), bukan
; (7-3.3=3.7V), tetap dingin & gak numpang ke rail yang khusus dijaga
; margin buat ESP32.
NET_5V_LOGIC -> LDO_3V3 (AMS1117-3.3 atau MCP1700-3.3, >=500mA) [PIN_IN]
NET_GND_BUS  -> LDO_3V3 [PIN_GND]
LDO_3V3 [PIN_OUT] -> NET_3V3_LOGIC
C_LDO_IN  (100nF) [PIN_1] -> NET_5V_LOGIC
C_LDO_IN          [PIN_2] -> NET_GND_BUS
C_LDO_OUT (10uF)  [PIN_1] -> NET_3V3_LOGIC
C_LDO_OUT         [PIN_2] -> NET_GND_BUS

3. MOSFET POMPA — DISKRIT (ON/OFF sekarang, future-proof utk PWM speed nanti)
--------------------------------------------------------------------------------

; REVISI (v3.1): balik ke MOSFET, gantikan relay diskrit di v3.0.
; Alasan PINDAH LAGI (bukan asal bolak-balik -- ini keputusan sadar
; setelah membandingkan trade-off, atas permintaan Asad/Agung supaya ada
; ruang kalau nanti mau modifikasi kecepatan pompa):
;   (a) MENGHILANGKAN masalah yang sempat jadi TBD di v3.0: rating kontak
;       relay AC vs DC yang ambigu (lihat catatan lama, sekarang tidak
;       relevan lagi karena tidak ada kontak mekanis sama sekali).
;   (b) Solid-state, tidak ada kontak aus/arcing -- relevan kalau pompa
;       sering nyala-mati (tiap kali user minta air).
;   (c) FUTURE-PROOF: kalau nanti Agung/dosen ternyata mau kecepatan
;       pompa bisa diatur (mis. proporsional ke sesuatu), MOSFET tinggal
;       diganti dari digitalWrite() ke ledcWrite() (PWM) di firmware --
;       TIDAK PERLU ganti hardware/rewiring. Relay diskrit TIDAK bisa di-
;       upgrade ke PWM sama sekali (mekanis, cuma ON/OFF, mustahil
;       dimodulasi cepat tanpa merusak kontak).
;   (d) Part MOSFET yang dipakai (IRLB8721PbF) SUDAH diverifikasi ke
;       datasheet resmi Infineon di sesi ini sebelumnya (lihat verifikasi
;       di akhir file): Vgs(th) 1.35-2.35V (logic-level, nyala penuh di
;       gate drive 3.3V ESP32), Rds(on) maks 16mOhm @Vgs=4.5V, ID kontinu
;       62A @Vgs=10V/Tc=25C -- jauh di atas kebutuhan 5A pompa, margin
;       sangat besar, akan beroperasi dingin (estimasi P=I^2*Rds(on) ~
;       25*0.016 = 0.4W, tidak perlu heatsink).
; PENTING -- INI TETAP ON/OFF DI FIRMWARE SEKARANG, BUKAN PWM AKTIF:
; "future-proof" di sini artinya HARDWARE-nya siap kalau suatu saat
; dibutuhkan, TAPI firmware v3.1 ini TIDAK menambah logika modulasi
; kecepatan apa pun -- itu tetap di luar scope sampai ada permintaan
; konkret dari Agung (jangan diasumsikan sudah termasuk, sama seperti
; pelajaran dari kasus PID pompa-vs-heater kemarin -- jangan desain
; berdasarkan "siapa tahu" tanpa konfirmasi eksplisit kalau sudah soal
; logika kontrol, bukan cuma provisioning hardware).
;
; PIN: GPIO26 (sama seperti sebelumnya). ESP32 GPIO bisa langsung drive
; gate MOSFET logic-level lewat resistor seri, tidak perlu tahap
; transistor driver terpisah lagi (beda dari relay yang butuh BC337-40
; sbg driver koil).
ESP32_DEVKIT [PIN_GPIO26] -> R_GATE (100R) [PIN_1]
R_GATE [PIN_2] -> Q_PUMP (IRLB8721PbF) [PIN_GATE]

; Pull-down gate WAJIB -- tanpa ini, gate floating (high-Z) saat ESP32
; boot/reset bisa bikin MOSFET nyala sendiri sesaat sebelum firmware jalan
; dan set pin ke LOW. Default state MOSFET harus OFF selama kondisi tidak
; pasti (boot, brown-out, dll).
Q_PUMP [PIN_GATE]   -> R_GATE_PD (10k) [PIN_1]
R_GATE_PD [PIN_2] -> NET_GND_BUS

Q_PUMP [PIN_SOURCE] -> NET_GND_BUS

; Logika: ACTIVE-HIGH.
; GPIO26 = HIGH -> gate MOSFET > Vgs(th) -> MOSFET ON (low Rds(on)) ->
; pompa ON, air mengalir ke keran.
; GPIO26 = LOW  -> gate ditarik R_GATE_PD ke GND -> MOSFET OFF -> pompa OFF.
; GERBANG SUHU MALAM (DIKONFIRMASI dari diskusi, TIDAK BERUBAH dari v3.0):
; malam hari, pompa TIDAK langsung ON begitu diminta -- tunggu dulu sampai
; T_tangki capai setpoint (heater kerja duluan menaikkan suhu), baru pompa
; diizinkan ON. Siang hari air sudah dihangatkan matahari sepanjang hari
; (thermosiphon), jadi pompa boleh langsung ON begitu diminta tanpa
; nunggu. Detail logika lengkap di bagian 9.

; === JALUR DAYA POMPA (DC 12V, TIDAK ADA HUBUNGAN DENGAN AC/PLN) ===
; Low-side switch: pompa+ permanen ke +12V, pompa- di-switch ke GND lewat
; MOSFET. JANGAN sampai pompa+ juga nyambung langsung ke 12V bus DAN ke
; drain MOSFET sekaligus (itu bug topologi yang pernah kejadian di draft
; sebelumnya di proyek ini -- kalau begitu switching-nya kebypass, pompa
; selalu full-on apa pun state MOSFET).
NET_12V_BUS (sisi FUSE_PUMP) -> POMPA_DC [PIN_+]
POMPA_DC [PIN_-] -> Q_PUMP (IRLB8721PbF) [PIN_DRAIN]

; Dioda flyback di terminal pompa -- WAJIB, motor DC = beban induktif,
; melindungi MOSFET dari back-EMF saat pompa dimatikan. SB1040 (10A/40V
; Schottky), margin 2x di atas arus pompa 5A -- part & posisi sama persis
; dengan versi relay sebelumnya, cuma titik sambung di sisi POMPA_DC[-]
; sekarang ke drain MOSFET, bukan ke kontak NO relay.
D_PUMP (SB1040, 10A/40V Schottky) [PIN_ANODE]   -> POMPA_DC [PIN_-]
D_PUMP                             [PIN_CATHODE] -> POMPA_DC [PIN_+]

; CATATAN: kabel fisik (bukan trace PCB) dari terminal blok ke pompa --
; pakai minimal AWG18 (0.75mm^2) untuk arus 5A, AWG16 kalau kabelnya
; panjang (>1m). Trace PCB drain-source MOSFET + jalur ke pompa tetap
; perlu lebar sesuai bagian 8 (arusnya tidak berubah, 5A).
;
; DIHAPUS dari v3.0 (tidak relevan lagi krn tidak ada kontak mekanis):
; Q_PUMPREL (BC337-40), R_PUMPREL_B, D_PUMPREL, RELAY_POMPA (coil+kontak),
; R_SNUB/C_SNUB (snubber itu utk redam arcing KONTAK relay -- MOSFET
; tidak punya kontak mekanis, jadi tidak butuh snubber jenis ini).

4. SSR HEATER — SOLID STATE RELAY (PID time-proportional control)
--------------------------------------------------------------------------------

; REVISI ARSITEKTUR (v3.0): PID PINDAH KE SINI. PV = suhu tangki (DS18B20
; #2, GPIO5), MV = duty cycle time-proportional ke SSR (mis. window 1
; detik: duty 40% = SSR ON 0.4 detik, OFF 0.6 detik, berulang). Alasan
; SSR bukan relay mekanik: PID switching cepat & berulang terus-menerus
; akan mengaus kontak relay mekanik dalam waktu singkat -- SSR solid-
; state (opto-TRIAC internal), tidak ada bagian bergerak, aman di-switch
; sesering apapun. SSR dipilih atas DIMMER AC (phase-angle control)
; karena proses termal ini lambat (konstanta waktu menit), granularitas
; time-proportional 1 detik jauh lebih dari cukup -- dimmer cuma nambah
; kompleksitas (butuh deteksi zero-cross presisi + timing interrupt) dan
; risiko EMI/noise ke sensor DS18B20/I2C di board yang sama tanpa manfaat
; nyata di aplikasi ini.
;
; PEMILIHAN SSR: tipe ZERO-CROSS (bukan random-fire/instant-on) --
; direkomendasikan utk beban resistif seperti elemen pemanas karena
; switching selalu di titik nol gelombang AC, minim EMI/inrush. Contoh
; part umum: Fotek SSR-25DA atau sejenis (rating 25A/220V AC output,
; input kontrol 3-32VDC) -- ASUMSI rating input kontrol part yang
; benar-benar dibeli, WAJIB dicek datasheet spesifik (lihat catatan
; verifikasi di akhir file, BELUM diverifikasi ke datasheet resmi di
; revisi ini). Rating 25A jauh di atas kebutuhan aktual (~2.27A @ 500W/
; 220V) -- margin besar ("paling robust"), sekaligus rating umum yang
; gampang dicari & harganya terjangkau di marketplace lokal.
;
; SSR modern kebanyakan sudah include optocoupler/isolasi internal di
; sisi kontrol -- TIDAK perlu transistor driver terpisah seperti relay
; mekanik (beda dari desain pompa di bagian 3). Cukup GPIO -> resistor
; seri -> pin kontrol SSR.

; PIN: GPIO27 (sebelumnya dipakai utk relay mekanik heater, sekarang
; langsung ke SSR -- PWM/time-proportional dari firmware, bukan LEDC
; hardware PWM, karena periodenya lambat ~1 detik, cukup software timer).
ESP32_DEVKIT [PIN_GPIO27] -> R_SSR_SIG (220R) [PIN_1]   ; batasi arus ke opto internal SSR
R_SSR_SIG [PIN_2] -> SSR_HEATER [PIN_CTRL_+]
NET_GND_BUS -> SSR_HEATER [PIN_CTRL_-]

; Logika: ACTIVE-HIGH (GPIO27=HIGH -> SSR konduksi -> heater dapat daya
; AC). Digerbang oleh status MALAM dari sensor cahaya BH1750 (bagian 6):
; PID heater cuma AKTIF (dihitung & dieksekusi) kalau malam TERDETEKSI --
; siang hari SSR dipaksa OFF terlepas dari hasil PID (siang pemanasan
; murni dari kolektor pasif). Detail logika lengkap di bagian 9.

; === SISI DAYA AC (220V) — JALUR TERPISAH TOTAL DARI PCB LOGIC/DC ===
; SSR load-side (output AC) WAJIB dikabel eksternal lewat terminal blok,
; TIDAK lewat trace tembaga PCB -- sama prinsipnya dengan desain relay
; sebelumnya. SSR sendiri boleh dipasang di PCB yang sama (isolasi
; internal opto-TRIAC sudah didesain utk ini, sama seperti relay bare),
; TAPI SSR untuk beban 500W WAJIB pakai HEATSINK -- SSR TRIAC based
; punya rugi konduksi (~1-1.5V drop tipikal) yang di 2.27A menghasilkan
; disipasi panas ~2.5-3.5W terus-menerus saat ON, jauh lebih besar dari
; MOSFET/relay mekanik, dan TIDAK aman dibiarkan tanpa heatsink untuk
; beban sebesar ini -- WAJIB ditambahkan ke BOM (lihat bagian 10).
STEKER_AC [PIN_HOT] -> FUSE_AC (3A) [PIN_A]
FUSE_AC [PIN_B] -> SSR_HEATER [PIN_LOAD_IN]
SSR_HEATER [PIN_LOAD_OUT] -> ELEMEN_PEMANAS [PIN_HOT]
ELEMEN_PEMANAS [PIN_NEUTRAL] -> STEKER_AC [PIN_NEUTRAL]

; === PERINGATAN -- ELEMEN PEMANAS YANG DIBELI TIDAK DIRANCANG UNTUK
; INSTALASI TETAP TERCELUP, INI PERLU DIDISKUSIKAN, BUKAN CUMA DICATAT ===
; Produk yang dibeli client: "elemen celup" konsumen 500W/220V, ukuran fisik
; cuma 16 x 3.5 x 1.5 cm, warna pink, bodi plastik+elemen besi -- ini jenis
; pencelup cepat-didih untuk gelas/teko/panci RUMAH TANGGA (dipegang tangan,
; dicelup sebentar, dicabut lagi), BUKAN elemen tubular/tangki yang memang
; didesain untuk instalasi permanen tercelup terus-menerus di tangki SWH.
; Ada 2 isu teknis nyata yang HARUS didiskusikan ke Agung/dosen pembimbing
; sebelum lanjut, bukan sekadar diasumsikan aman:
;   1. LABEL PRODUK SENDIRI bilang "Hindari mencelupkan gagang pegangan
;      tangan dari alat ini kedalam air" -- artinya cuma ujung elemen yang
;      boleh basah, sisi gagang/kabel WAJIB tetap kering. Untuk instalasi
;      tetap di tangki (bukan dipegang tangan), ini berarti perlu BRACKET/
;      DUDUKAN MEKANIK yang menahan elemen di posisi tetap dengan gagang
;      selalu di atas permukaan air -- ini kerjaan mekanik/rangka, di luar
;      scope PCB+firmware Asad, tapi WAJIB disampaikan ke Agung karena kalau
;      salah pasang (gagang ikut tercelup atau bergeser turun), risiko
;      korslet/sengatan listrik nyata.
;   2. TIDAK ADA INFORMASI proteksi dry-fire/thermal cutoff di deskripsi
;      produk (beda dengan elemen tubular water heater tangki yang biasanya
;      punya thermal fuse bawaan). Kalau SSR ON tapi permukaan air di
;      tangki turun di bawah elemen (kebocoran, evaporasi) -- elemen
;      konsumen seperti ini punya risiko overheat/rusak/kebakaran lebih
;      tinggi dibanding elemen tubular yang memang dirancang untuk
;      submerged permanent duty.
; REKOMENDASI (opsional, di luar scope asli tapi masuk akal ditambahkan ke
; firmware+wiring karena keduanya memang bagian kerjaan Asad): tambah SATU
; interlock keselamatan level-air (float switch sederhana, 2 kabel, NO/NC)
; yang dipasang di titik tinggi minimum aman elemen -- firmware paksa
; GPIO27=LOW (heater OFF paksa, terlepas dari status PID) kalau float
; switch mendeteksi air di bawah ambang. Ini TIDAK ada di netlist versi
; ini (belum dikonfirmasi client mau atau tidak) -- SAMPAIKAN opsi ini ke
; Agung sebagai rekomendasi keselamatan, bukan langsung ditambahkan
; sepihak, karena menambah 1 pin digital + 1 komponen BOM + logika
; firmware baru.

5. DS18B20 x2 (SENSOR SUHU KOLEKTOR & TANGKI)
--------------------------------------------------------------------------------

; REVISI (v3.0): PV (process variable) untuk loop PID SEKARANG DI HEATER
; (bukan pompa lagi, lihat bagian 3&4) = SENSOR TANGKI. Sensor kolektor
; (dipasang di ujung output kolektor, sesuai proposal asli) sekarang
; statusnya MONITORING/LOGGING saja (tampilan LCD + data analisis
; "pengaruh cuaca" di bab hasil skripsi) -- BUKAN bagian hitungan PID,
; karena aktuator yang dulu dia kontrol (sirkulasi kolektor) sudah tidak
; ada (jalur itu sekarang pasif/thermosiphon). Interlock lama "pompa OFF
; kalau T_kolektor<=T_tangki" juga SUDAH TIDAK RELEVAN dan dihapus dari
; firmware notes (bagian 9) -- pompa sekarang cuma soal distribusi,
; gerbangnya beda (lihat bagian 9).

; PIN GANTI dari D2/D3 (Mega) -> GPIO4/GPIO5 (ESP32). RAIL PULL-UP GANTI
; dari NET_5V_LOGIC -> NET_3V3_LOGIC (WAJIB -- DS18B20 sendiri toleran 3.3V
; atau 5V, tapi pull-up-nya HARUS ikut rail yang sama dengan level logic
; ESP32, supaya tegangan HIGH di pin data = 3.3V, bukan 5V yang bisa
; merusak GPIO).

; --- Sensor kolektor (DS18B20 #1) ---
NET_3V3_LOGIC -> DS18B20_1 [PIN_VCC]
NET_GND_BUS   -> DS18B20_1 [PIN_GND]
ESP32_DEVKIT [PIN_GPIO4] -> DS18B20_1 [PIN_DATA]
NET_3V3_LOGIC -> R_DS1_PU (4k7) [PIN_1]
R_DS1_PU [PIN_2] -> ESP32_DEVKIT [PIN_GPIO4]   ; pull-up OneWire, WAJIB, ke 3.3V

; --- Sensor tangki (DS18B20 #2) — INI YANG JADI PV UNTUK PID ---
NET_3V3_LOGIC -> DS18B20_2 [PIN_VCC]
NET_GND_BUS   -> DS18B20_2 [PIN_GND]
ESP32_DEVKIT [PIN_GPIO5] -> DS18B20_2 [PIN_DATA]
NET_3V3_LOGIC -> R_DS2_PU (4k7) [PIN_1]
R_DS2_PU [PIN_2] -> ESP32_DEVKIT [PIN_GPIO5]   ; pull-up OneWire, WAJIB, ke 3.3V

; Dua sensor dipasang di OneWire bus TERPISAH (GPIO4, GPIO5) -- bukan satu
; bus bersama. Lebih boros 1 pin, tapi lebih simpel di firmware (tidak
; perlu scan ROM address 64-bit tiap sensor), dan lebih gampang di-debug
; kalau salah satu sensor bermasalah. GPIO4/5 dipilih karena aman dari
; strapping pin (hindari GPIO0/2/12/15) dan bukan pin flash internal
; (hindari GPIO6-11).

; DIKONFIRMASI dari client: kedua sensor TERCELUP LANGSUNG di air (bukan
; ditempel di luar pipa). Konsekuensi mekanik/instalasi (di luar scope
; PCB, tapi penting buat firmware & pemilihan part):
;   - WAJIB pakai probe DS18B20 waterproof (ujung stainless steel yang
;     sudah di-epoxy/potting pabrik) -- bukan chip DS18B20 telanjang TO-92.
;   - Titik masuk kabel probe ke dinding tangki/kolektor WAJIB pakai cable
;     gland/grommet kedap air (proposal asli sudah sebut lubang 15mm di
;     tangki yang bisa dipakai untuk ini -- pastikan disegel, bukan cuma
;     dilubangi polos, supaya air tidak rembes ke kabel/elektronik).
;   - Panjang kabel probe ke PCB bisa cukup jauh (tangki/kolektor di luar,
;     box kontrol biasanya di dalam/terlindung) -- pull-up 4k7 di bagian
;     ini sudah cukup untuk kabel sampai beberapa meter; kalau instalasi
;     akhir ternyata >5m, pertimbangkan turunkan nilai pull-up (mis. 3k3)
;     atau tambah kapasitor kecil (~100pF) di pin data dekat Arduino untuk
;     redam noise pada bus OneWire yang panjang.

; DIKONFIRMASI: LCD karakter (kristal/HD44780-type) dengan backpack I2C
; -- sesuai yang sudah dipakai di proposal asli, tidak diganti.
; BARU (v2.0): tambah sensor cahaya BH1750 (I2C digital lux meter) untuk
; deteksi malam/siang, atas permintaan client.
; REVISI (v3.1) -- INPUT SETPOINT PINDAH DARI ENCODER FISIK KE WEB/WEBSOCKET:
; atas keputusan client, rotary encoder + push button DIHAPUS dari hardware.
; Setpoint sekarang di-set lewat halaman web sederhana yang di-hosting
; LANGSUNG oleh ESP32 sendiri (WiFi sudah onboard, TIDAK perlu modul/
; komponen tambahan) -- ESP32 jalan sbg WiFi AP atau connect ke WiFi
; rumah (STA mode), serve 1 halaman HTML + WebSocket, browser HP kirim
; nilai setpoint baru real-time lewat WebSocket. LCD TETAP ADA untuk baca
; status lokal (suhu, setpoint aktif, status heater/pompa) tanpa perlu

; dulu", jadi desain ini SENGAJA tidak pakai cloud/app pihak ketiga
; (Blynk/ThingSpeak dkk) supaya tidak ada dependency internet -- cukup
; WiFi lokal antara HP dan ESP32, lebih predictable buat demo sidang
; (lihat diskusi risiko availability sebelumnya). KONSEKUENSI BOM: hapus
; ENCODER + R_ENC_CLK/R_ENC_DT (kalau bare) dari daftar beli -- 2 GPIO
; (25, 32, 33 -- 3 pin) jadi bebas, bisa dipakai lain kalau perlu nanti.
; CATATAN: ini scope tambahan di luar apa yang disebut proposal tertulis
; (yang sama sekali tidak menyebut web/IoT) -- sama seperti heater,
; idealnya disebutkan juga ke dosen pembimbing sbg fitur tambahan,
; walau risikonya lebih rendah drpd isu PID krn ini cuma nambah HMI,
; tidak mengubah klaim kontrol inti skripsi.

; === LCD I2C — WAJIB LEWAT LEVEL SHIFTER (konsekuensi ganti ke ESP32) ===
; LCD backpack (PCF8574) UMUMNYA punya pull-up SDA/SCL onboard yang narik
; ke VCC-nya sendiri. Kalau LCD di-supply 5V (biar backlight terang &
; kontras normal sesuai spek LCD kebanyakan), pull-up itu akan menarik
; SDA/SCL ke ~5V -- itu MELEBIHI batas aman GPIO ESP32 (3.3V, tidak
; toleran 5V). INI BUKAN OPSIONAL, WAJIB ADA SALAH SATU dari solusi ini:
;   (a) Level shifter I2C bidirectional aktif (mis. modul breakout
;       berbasis BSS138, atau 2x MOSFET BSS138 diskrit + 4 resistor
;       pull-up dirakit sendiri di PCB kalau mau konsisten dengan gaya
;       "driver diskrit sendiri" di proyek ini) di antara ESP32 (sisi
;       3.3V) dan LCD backpack (sisi 5V) -- REKOMENDASI Asad, paling
;       robust & tidak korbankan brightness/kontras LCD.
;   (b) LCD backpack di-supply 3.3V (bukan 5V) -- lebih sederhana/murah
;       (tidak perlu part tambahan) TAPI backlight jadi lebih redup dan
;       kontras mungkin perlu di-trim ulang potentiometer-nya, dan tidak
;       semua backpack PCF8574 dijamin beroperasi normal di 3.3V (banyak
;       yang toleransi turun ke 2.5V, tapi VERIFIKASI ke part yang benar-
;       benar dibeli, bukan diasumsikan).
; !! KOREKSI PENTING (BUKAN OPSI): resistor divider/resistor seri BIASA
; TIDAK BISA dipakai sbg pengganti (a) di atas. I2C itu bus open-drain
; DUA ARAH (ESP32 dan LCD sama-sama bisa narik SDA/SCL ke LOW), sedangkan
; resistor divider cuma benar utk sinyal SATU ARAH (mis. UART TX 5V ->
; RX 3.3V, atau baca sensor analog). Kalau dipaksa pakai divider di bus
; I2C: ESP32 tidak bisa menarik LOW dgn valid ke sisi 5V (tegangan yg
; sampai ke sisi 5V pas ESP32 coba LOW tergantung rasio R1/R2, biasanya
; tidak cukup rendah utk dianggap valid LOW oleh chip 5V), jadi write
; dari ESP32 ke LCD bisa gagal random -- BUKAN solusi yg reliable utk
; sesuatu yg harus dipertanggungjawabkan di sidang. Trik "1 resistor seri
; saja" (tanpa divider, cuma limiting) kadang dipakai hobbyist krn
; kelihatan "jalan", tapi itu mengandalkan clamp diode internal GPIO
; ESP32 menyerap arus lebih dari spek resmi Espressif -- di luar spek,
; berisiko random fail, TIDAK direkomendasikan. Solusi hemat part yg
; TETAP benar secara elektris: opsi (a) di atas versi diskrit (2x BSS138
; + resistor), bukan resistor polos.
; Netlist ini pakai opsi (a) sebagai desain utama.

NET_5V_LOGIC -> LCD_I2C [PIN_VCC]
NET_GND_BUS  -> LCD_I2C [PIN_GND]
LCD_I2C [PIN_SDA] -> LVL_SHIFT [PIN_HV_SDA]
LCD_I2C [PIN_SCL] -> LVL_SHIFT [PIN_HV_SCL]
NET_5V_LOGIC  -> LVL_SHIFT [PIN_HV]
NET_3V3_LOGIC -> LVL_SHIFT [PIN_LV]
NET_GND_BUS   -> LVL_SHIFT [PIN_GND]
LVL_SHIFT [PIN_LV_SDA] -> ESP32_DEVKIT [PIN_GPIO21_SDA]
LVL_SHIFT [PIN_LV_SCL] -> ESP32_DEVKIT [PIN_GPIO22_SCL]
C_LCD_CER (100nF) [PIN_1] -> LCD_I2C [PIN_VCC]
C_LCD_CER          [PIN_2] -> NET_GND_BUS
; Alamat I2C backpack ASUMSI 0x27 -- cek dengan I2C scanner, bisa juga 0x3F.

; === SENSOR CAHAYA BH1750 (BARU, I2C, share bus SAMA dengan LCD) ===
; BH1750 beroperasi native 3.3V-5V, output digital I2C -- DIPILIH
; dibanding LDR analog karena lebih presisi (lux terukur, bukan tegangan
; mentah yang perlu kalibrasi manual per unit LDR) dan lebih mudah di-

ESP32_DEVKIT [PIN_GPIO22_SCL] -> BH1750 [PIN_SCL]   ; (beda address dgn LCD:
                                                       ; BH1750 default 0x23,
                                                       ; LCD 0x27 -- tidak
                                                       ; bentrok)
BH1750 [PIN_ADDR] -> NET_GND_BUS   ; pin ADDR ke GND -> address 0x23

; DIHAPUS di v3.1: rotary encoder + push button (GPIO25/32/33 dari versi

8. CATATAN PENTING PCB LAYOUT

LEBAR TRACE (minimum, estimasi, 1oz copper, ~10 C rise -- pompa DIKONFIRMASI
5A):
  NET_12V_BUS (sebelum fuse cabang)  : 2mm  (harus tanggung ~5.5A total)
  Jalur pompa (setelah FUSE_PUMP)    : 1.8mm (5A)
  NET_7V_ESP (BARU v3.1)             : 0.4mm (beban kecil, cuma ESP32 devkit)
  NET_5V_LOGIC (skrg cuma LCD+input LDO)  : 0.4mm
  NET_3V3_LOGIC                      : 0.4mm (beban kecil, sensor+BH1750+LV shifter)
  Sinyal (SDA/SCL/GPIO4/5/26/27)     : 0.3mm

; CATATAN BARU: jalur dari BATERAI ke FUSE_MAIN (sebelum masuk PCB) tetap
; pakai KABEL, bukan trace PCB -- baterai dan charge controller/panel
; letaknya di luar PCB kontrol (biasanya di dekat panel/box baterai
; terpisah), cuma titik masuk 12V yang menyentuh PCB lewat terminal blok.

; Kalau board yang dipakai 1oz copper dan lebar 1.8-2mm untuk jalur
; pompa terasa terlalu lebar/tidak muat di layout, opsi lain: minta fab
; PCB pakai 2oz copper (lebar trace bisa dikira-kira setengahnya untuk
; kenaikan suhu yang sama), atau jalur pompa TIDAK lewat trace PCB sama
; sekali -- pompa langsung dikabel dari terminal blok lewat drain MOSFET
; ke pompa dengan kabel AWG18 (lihat catatan bagian 3), PCB cuma
; menyalurkan sisi gate (arus kecil) saja. Opsi kedua ini yang lebih
; umum dipakai untuk board hobbyist/skripsi karena tidak perlu pesan fab
; dengan copper lebih tebal.

GROUND PLANE:
  - Copper pour GND di layer bawah
  - Star ground: satukan semua GND di SATU titik dekat terminal negatif
    BATERAI (dulu "PSU" -- sekarang sumbernya baterai 12V dari sistem
    panel surya, titik referensi ground-nya sama prinsipnya)
  - Kabel sensor DS18B20 (terutama yang ke kolektor, sering kabelnya panjang
    kalau kolektor jauh dari box kontrol) jangan lewat dekat jalur pompa/MOSFET
  - Charge controller MPPT biasanya punya ground sendiri dari sisi panel --
    pastikan cuma ADA SATU titik sambung ke ground sistem PCB (di titik
    negatif baterai), jangan bikin ground loop dengan menyambung ground
    panel/charge controller ke PCB di titik lain juga

ZONA AC 220V:
  - SSR_HEATER boleh nempel di PCB yang sama (isolasi opto-TRIAC internal
    sudah didesain utk ini), TAPI wiring AC dari steker dan ke elemen
    pemanas WAJIB lewat terminal blok, TIDAK lewat trace PCB
  - SSR_HEATER WAJIB pakai heatsink (lihat bagian 4 & BOM) -- beri ruang
    di layout utk heatsink + sirkulasi udara, jangan padatkan komponen
    lain persis di sebelahnya
  - Beri jarak fisik minimum antara footprint SSR dan komponen logic
    lain di sekitarnya -- jangan taruh apapun persis di sisi kontak/load
  - FUSE_AC dan terminal blok AC ditaruh di tepi PCB, gampang dijangkau
    dan gampang diganti kalau fuse putus

ZONA MOSFET POMPA (DC, drain-source menanggung 5A -- lihat catatan
bagian 3):
  - Q_PUMP (IRLB8721) ditaruh dengan trace drain/source selebar jalur
    pompa di bagian 8 (1.8-2mm), BUKAN selebar trace sinyal biasa
  - Trace gate (R_GATE ke pin gate) boleh sinyal biasa (0.3mm), pendek
    dan langsung -- hindari rute gate panjang/berkelok yang bisa
    menangkap noise dan memicu switching liar
  - Meskipun estimasi disipasi kecil (~0.4W, lihat bagian 3), sediakan
    sedikit copper pour di sekitar tab/drain MOSFET sebagai heatsink pasif
    -- praktik baik walau tidak wajib di beban 5A ini

PENEMPATAN KOMPONEN:
  - Kedua buck converter (BUCK_ESP, BUCK_LCD) & LDO 3V3 di tepi PCB, ada sirkulasi udara
  - Kapasitor decoupling 100nF sedekat mungkin ke pin VCC tiap modul
  - SSR_HEATER dan Q_PUMP (MOSFET, yang membawa arus lebih besar/panas)
    dijauhkan sedikit dari ESP32 devkit dan sensor
  - Level shifter I2C ditaruh dekat konektor LCD (sisi 5V-nya menghadap
    LCD, sisi 3.3V-nya menghadap ESP32) supaya jalur 5V tidak menjalar
    jauh di board
  - Mounting hole untuk pemasangan ke box/chassis kontrol
  - Silkscreen label jelas tiap konektor eksternal (bukan cuma "J1"/"J2"
    -- tulis "SENSOR TANGKI", "POMPA", "AC IN", "HEATER OUT", "BATERAI IN",
    dst)
  - Charge controller MPPT & baterai TIDAK di PCB ini -- part terpisah,
    ditaruh di box/enclosure sendiri dekat panel surya/baterai, PCB
    kontrol cuma terima 12V dari situ lewat terminal blok + kabel

9. CATATAN FIRMWARE
--------------------------------------------------------------------------------

  REVISI TOTAL (v3.0) -- PID PINDAH KE HEATER, lihat catatan versi 3.0
  poin 0 di awal file untuk alasan lengkapnya (thermosiphon pasif +
  pompa cuma distribusi).

  - PID SEKARANG DI HEATER, bukan pompa. PV = suhu TANGKI (GPIO5). Output
    PID (0-100%) dikonversi jadi duty cycle time-proportional ke SSR:
      window = 1000 ms (ASUMSI awal, bisa disesuaikan hasil tuning)
      t_on   = (Output_PID / 100.0) * window
      SSR = HIGH selama t_on ms tiap window, LOW sisanya
    PID cuma DIHITUNG & DIEKSEKUSI kalau is_night == true (lihat gerbang
    siang/malam di bawah) -- siang hari SSR dipaksa LOW terlepas dari
    hasil PID, karena pemanasan siang murni dari kolektor pasif
    (thermosiphon), bukan tugas heater.
  - GERBANG SIANG/MALAM (dari sensor cahaya BH1750, bagian 6):
      is_night = lux_BH1750 < AMBANG_LUX   ; ASUMSI ambang ~10 lux, WAJIB
                                             ; dikalibrasi di lokasi asli
    Siang (is_night==false): SSR heater dipaksa LOW, PID heater di-reset
    (integrator dikosongkan) supaya tidak ada windup menumpuk dari siang
    hari yang tiba-tiba nongol pas malam mulai.
  - ANTI-WINDUP: integrator PID heater berhenti akumulasi saat output
    saturasi di 0% atau 100%, DAN direset tiap kali transisi siang->malam
    (lihat poin di atas).
  - SENSOR KOLEKTOR (GPIO4): dibaca tiap siklus loop, ditampilkan LCD +
    dicatat/logged (kalau ada logging ke SD/serial) untuk data analisis
    "pengaruh cuaca terhadap kinerja" di bab hasil skripsi -- TIDAK masuk
    ke perhitungan PID atau kondisi apa pun (murni instrumentasi).
  - POMPA (MOSFET ON/OFF, GPIO26, active-HIGH -- lihat bagian 3): dipicu
    oleh permintaan user (mis. tombol/switch "ambil air" -- MEKANISME
    PEMICU INI BELUM DIKONFIRMASI, lihat TBD) dengan gerbang suhu:
      Siang (is_night==false): pompa ON langsung begitu diminta (air
      sudah dihangatkan matahari sepanjang hari via thermosiphon).
      Malam (is_night==true): pompa TIDAK langsung ON. Firmware tunggu
      sampai T_tangki >= setpoint (heater sudah bekerja menaikkan suhu),
      BARU pompa diizinkan ON. Selama menunggu, LCD idealnya tampilkan
      status "memanaskan..." supaya user tahu kenapa air belum keluar.
      TIMEOUT (BARU, disarankan): kasih batas waktu tunggu maksimum (mis.
      10-15 menit ASUMSI, WAJIB disesuaikan hasil tuning PID riil) --
      kalau heater tidak berhasil capai setpoint dalam waktu itu (elemen
      rusak, air terlalu dingin, dll), pompa tetap diizinkan ON dengan
      suhu apa adanya + LCD tampilkan peringatan, supaya user tidak
      terjebak menunggu tanpa batas kalau ada masalah hardware.
  - CATATAN v3.1 -- FIRMWARE POMPA TETAP ON/OFF (digitalWrite), BUKAN
    PWM: hardware GPIO26 sekarang di gate MOSFET (bukan lagi basis
    transistor driver relay), yang secara fisik SIAP dipakai PWM
    (ledcAttachPin/ledcWrite) kalau suatu saat dibutuhkan kecepatan
    variabel. TAPI firmware v3.1 ini sengaja TIDAK menambah logika PWM
    apa pun -- itu tetap di luar scope sampai ada permintaan konkret dari
    Agung. Jangan tambahkan modulasi kecepatan pompa sendiri tanpa
    konfirmasi eksplisit.
  - SETPOINT (BARU v3.1, ganti dari encoder): ESP32 host web server +
    WebSocket sendiri (WiFi AP mode ATAU STA connect ke WiFi rumah --
    WAJIB dipilih & dikonfirmasi, lihat TBD). Halaman web sederhana (1
    halaman HTML, bisa disimpan sbg PROGMEM/SPIFFS di firmware, TIDAK
    perlu hosting eksternal) kirim nilai setpoint baru real-time lewat
    WebSocket begitu user ubah. Validasi range setpoint tetap WAJIB di
    firmware (mis. clamp ke rentang suhu aman, mis. 30-70C ASUMSI --
    jangan percaya input browser mentah-mentah).
  - LCD menampilkan: suhu tangki (PV), suhu kolektor (monitoring), setpoint
    aktif, status heater (ON/OFF + malam/siang dari BH1750), status pompa
    (ON/OFF/menunggu-panas), dan idealnya level baterai (lihat TBD -- perlu
    sensor tegangan baterai tambahan kalau mau ditampilkan, belum ada di
    netlist ini).
